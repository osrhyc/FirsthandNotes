## 今日主线

今天的主线是“规模增长不等于利润兑现”：鸿蒙宣布终端规模跨过一亿，品牌电商服务商宝尊收入增长但经营亏损扩大，奇富科技则在收入、贷款规模和利润同比承压中继续收紧风险。技术侧有两条可落地的变化：GitHub 将调整通知订阅逻辑，OpenAI 把医疗证据检索配置开放给 API 组织；另有一项蛋白设计研究仍处在早期验证阶段。预算与注意力正在流向平台适配、品牌经营效率、风险控制和高可信专业工作流，而不是单纯追逐用户数或模型演示。

## 速览

- 华为称 HarmonyOS 5/6/7 手机、平板和电脑设备数超过 1 亿；此为公司口径，不等同于活跃用户或付费用户。
- 宝尊 Q3 总收入同比增 10.7%，但经营亏损扩大，电商与品牌管理分部调整后经营亏损均需关注。
- 奇富科技 Q3 促成及发放贷款总额同比降 40.6%，公司提到行业流动性与监管压力、风险表现恶化。

## 重点详读

### 1. 鸿蒙终端设备数破亿，机会在真实适配而非追逐注册数字

**发生了什么：**华为 11 月 24 日称，搭载 HarmonyOS 5/6/7 的手机、平板和电脑设备超过 1 亿，可获取的应用和服务超过 46 万，注册开发者超过 1200 万；并披露开源鸿蒙有 1.4 万余名贡献者、120 余个行业发行版。以上均为华为披露数据，未见此处提供第三方活跃度审计。

**为什么重要：**对应用团队而言，平台规模足以让“鸿蒙是否值得支持”从纯预研转为按用户结构、业务场景和维护成本核算的渠道决策。设备数不能说明应用留存、交易额或鸿蒙原生开发者的收入。

**建议/行动：**如果产品用户中有华为设备用户，先抽样看客服、埋点和客户名单，估算目标人群占比；对 1 个高频功能做兼容性盘点，测量适配、审核、测试和后续版本维护的总成本，再决定是否做原生体验。

**风险边界：**不要把累计终端规模当作月活，也不要默认 Android 包、支付、推送和系统能力可无改造迁移。来源：[华为公告](https://www.huawei.com/cn/news/2026/11/harmonyos-system)。

### 2. 宝尊收入增长、亏损扩大，品牌代运营要看利润结构

**发生了什么：**宝尊 11 月 24 日公布未经审计 Q3 业绩：总收入 23.86 亿元，同比增长 10.7%；电商业务收入增 6.3%，品牌管理收入增 32.2%。但经营亏损由去年同期 2560 万元扩大至 5110 万元，销售与营销费用同比增加；品牌管理分部收入 5.24 亿元，期末管理 216 家线下门店。

**为什么重要：**这是品牌服务市场的现实样本：商品销售与品牌管理业务在增长，但获客、线下扩张与运营支出可能吞掉收入增量。小团队可切入的往往是单一环节服务，而非复制重资产的全盘代运营。

**建议/行动：**选一个细分品类访谈 5 家商家，核对其内容投放、客服、上新、库存同步中最耗时且可量化的环节；以固定范围、固定周期收费做小试点，约定指标和数据权限。

**风险边界：**收入、分部增长与管理层 2028 年盈利目标均来自公司披露；目标不是结果。宝尊整体仍亏损，单一增长率不能证明品类普遍景气。来源：[宝尊投资者关系公告](https://ir.baozun.com/2026-11-24-Baozun-Announces-Third-Quarter-2026-Unaudited-Financial-Results)。

### 3. 奇富科技贷款规模明显收缩，信贷平台先看风险而非表面利润

**发生了什么：**奇富科技披露 Q3 促成及发放贷款总额 494.69 亿元，同比下降 40.6%；期末贷款余额 931.94 亿元，同比下降 32.5%。收入为 30.885 亿元，净利润 3.805 亿元；公司称行业流动性收紧、监管趋严且风险表现恶化，并预计 Q4 净利润同比下降 67%–77%。

**为什么重要：**金融科技平台的交易量、收入和利润可能同时受授信策略、资金方、逾期表现和监管约束影响。小商家或服务商若考虑给客户赊账、分期或做获客合作，应先识别坏账与资金占用，而非只看平台累计用户。

**建議/行动：**做一份客户账期压力测试：按 30/60/90 天回款情景测现金缺口，明确逾期催收、退款和坏账责任；不具备风控能力时优先现金结算或合规持牌合作。

**风险边界：**财报未经审计，展望为公司初步预期；不能将单家公司变化推断为全行业结论。来源：[奇富科技业绩公告（公司新闻稿）](https://www.mfn.se/one/a/qfin-holdings/qfin-holdings-announces-third-quarter-2026-unaudited-financial-results-c481688e)、[港交所公告日期披露](https://www.hkexnews.hk/listedco/listconews/sehk/2026/1112/2026111200497_c.pdf)。

### 4. 政府投资项目调度强调支付使用与项目储备，B2G 机会仍须等具体采购

**发生了什么：**国家发改委 11 月 23 日召开视频会议，要求加快政府投资项目建设和资金支付使用，强化要素保障，并提高项目前期工作和储备质量。

**为什么重要：**政策执行端同时提到“资金支付”和“项目储备”，意味着承包商的回款、项目合规材料、进度管理仍是现实运营议题。对小团队，围绕招投标材料、进度留痕、验收档案的工具或服务可能比直接承接大型工程更可控。

**建议/行动：**选一个公开招采平台和一个地区，观察未来两周实际挂出的项目、资质和付款条件；访谈供应商了解资料整理、验收对账的人工成本，先做可复用模板或按次服务。

**风险边界：**会议要求不等于资金已经拨付、订单已产生或付款期限统一。不得以政策表态承诺“拿补贴”“包回款”。来源：[国家发改委会议通报](https://www.ndrc.gov.cn/xwdt/xwfb/202611/t20261123_1409044.html)。

### 5. GitHub 通知规则将变更，维护者应检查依赖通知的自动化

**发生了什么：**GitHub 表示将于 12 月 1 日起分一周迁移 GitHub.com 通知行为：用户手动退订后，普通评论、评审提交、线程状态变化等不会再自动重新订阅；被提及、指派或请求评审仍会触发订阅。团队提及的通知也会更贴合当前成员关系。

**为什么重要：**依赖通知收件箱触发 triage、值班或工单自动化的团队，可能看到信号减少或行为变化。对独立开发者，这是一次低成本检查 webhook、邮件过滤和 issue 处理习惯的窗口。

**建议/行动：**在迁移期间抽查通知收件箱、订阅页和自建过滤规则；对关键仓库使用明确的指派、review request 和标签规则，不以“评论即订阅”作为唯一提醒机制。

**风险边界：**公告称无需用户操作，且不适用于 GitHub Enterprise Server；分批发布期间不同用户行为可能暂时不一致。来源：[GitHub Changelog](https://github.blog/changelog/2026-11-24-more-predictable-notifications-on-github-com/)。

### 6. OpenAI 医疗 API 配置支持证据检索，产品价值在引用与治理

**发生了什么：**OpenAI 11 月 24 日更新称，Astra、Sol 等医疗用途配置可供 API 组织通过 Responses API 使用；开启网络检索后，可查询专用医疗索引并以引用形式查找、比较和总结医疗证据。

**为什么重要：**面向医疗专业工作流，价值不只是生成文本，而是证据来源、可追溯性和合规边界。个人开发者更适合先做非诊断型文献整理、研究团队内部检索或引用核验工具。

**建议/行动：**先以公开论文和非个人健康数据做原型，评测引用准确率、漏引率、版本日期和失败提示；上线前逐项核实可用地区、适用组织、受保护健康信息处理条件与合同要求。

**风险边界：**厂商明确说明不替代专业医疗判断；API 组织可用不等于可直接处理受保护健康信息，PHI 还需相应协议与账户/工具配置。涉及患者数据、诊断或治疗建议须由合格专业人员和法律/隐私审查把关。来源：[OpenAI 模型更新说明](https://help.openai.com/en/articles/9624314-model-release-notes)、[API 医疗配置说明](https://help.openai.com/en/articles/20001656-healthcare-model-configurations-in-the-openai-api)。

### 7. 通用模型蛋白设计出现实验结合信号，但仍不是药物研发捷径

**发生了什么：**OpenAI 11 月 24 日发布预印本，称 GPT-6 系列可用推理与代码提出蛋白结构和序列；与 Onava 合作的实验中，依据 GPT-6.2 设计的蛋白在五个靶标上显示结合证据，候选筛选仍借助专用模型。

**为什么重要：**通用模型可能降低部分早期设计工作的工具门槛，给生物技术团队提供新的人机协作入口；但真正的商业壁垒仍在实验验证、候选筛选、稳定性与后续研发。

**建议/行动：**开发者可关注实验数据结构化、候选版本追踪、计算结果与实验结果对照等工具需求；先与实验室核实流程摩擦，不要开发或宣传未经验证的治疗方案。

**风险边界：**这是厂商预印本与合作实验的披露，不等同于独立复现；结合不证明特异性、稳定性、有效性、安全性或临床价值。来源：[OpenAI 研究说明及局限](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities/)。

### 8. 关于未发布模型安全担忧的报道尚未得到公开确认

**发生了什么：**Axios 11 月 24 日援引 20 多名匿名知情者称，部分 OpenAI 与 Anthropic 员工对未发布模型的安全风险和发布准备度有担忧；这是媒体单方报道，相关公司未在该报道中公开确认这些具体说法。

**为什么重要：**即使模型能力提升，安全评估、部署节奏、权限和事故响应仍可能影响 API 稳定性及企业采购。开发者应把模型替换、工具权限、人工审批和日志留存纳入产品设计，而不是假定能力越强就越适合自动执行。

**建议/行动：**给 Agent 操作设最小权限与人工确认门槛；对发信、付款、删除、生产环境写入等高影响操作保留审批和可回滚路径。

**风险边界：**匿名消息不能当作已证实事故、模型发布结论或公司立场。来源：[Axios 报道](https://www.axios.com/2026/11/24/anthropic-openai-unreleased-ai-safety-risks)。

## 非 AI 热点与传统商机

### 品牌电商的“增长与亏损并存”

宝尊公司披露显示，电商服务收入与品牌管理收入增长，但整体经营亏损扩大，营销开支同比上升。可验证的机会不是再做一套泛代运营，而是围绕一个品类的库存、客服、投放归因或门店/线上协同做窄服务。先用单店或单品牌试点证明节省工时或减少错发，再谈长期合同；平台投放成本、退货率和品牌授权是主要风险。

### 鸿蒙成为新增适配候选，但不要把用户规模当成交规模

公司披露的设备数与应用服务数说明生态已经形成可评估的覆盖面。可选方向包括小程序/应用迁移评估、企业内部应用适配、无障碍或跨设备体验测试。获客应从现有华为用户的产品数据、企业采购需求或合作伙伴渠道来，收费按评估/测试项目核算。维护兼容性与审核周期需要列入成本。

### 政府投资项目资料与验收环节存在服务假设

发改委会议强调项目支付和储备，不能据此断言采购潮已发生。可以做的低成本验证是梳理公开招采文件，访谈本地工程服务商，观察资料准备、验收归档、进度对账是否有重复劳动。收入可按项目整理或年度工具服务计费；须遵守招投标、档案、保密和供应商资质要求。

## 赚钱与市场方向

1. **垂直平台适配服务（非 AI）**：用户是已有鸿蒙客户或行业软件供应商；收费可按兼容性诊断、测试矩阵和迁移工时。获客从现有客户名单与开发服务商转介开始，先售卖一次诊断，不囤硬件。风险是生态变化导致重复维护，需在合同中界定支持版本。
2. **品牌经营数据与运营小服务（非 AI）**：用户是单品牌电商团队，付费点在客服、商品信息、库存与投放复盘。服务按月或按项目收费，流量来自行业社群、商家转介和公开案例内容。低成本验证：以匿名样本做一次经营诊断并争取付费试单；不得承诺 GMV 或未经授权读取平台数据。
3. **高可信医疗文献工作流（AI 辅助）**：付费者可能是研究机构、医药企业或专业团队，而非普通消费者；按团队席位或部署服务定价。先用公开文献核验引用准确度及审阅节省时间。医疗数据、监管、责任归属和错误引用使其不适合“先上线再补合规”。
4. **项目履约与验收资料服务（非 AI）**：面向小型供应商，按项目清单、归档和对账收费。用公开招标文件做模板，靠本地行业协会、会计/工程服务伙伴获客；先确认真实采购需求与付款周期。不要提供资质挂靠或规避招采规则的服务。

## 国内平台/自建站小生意观察

以下均为基于当日来源形成的验证假设，不是平台热销榜或已证实的流量红利。

### 闲鱼：鸿蒙应用适配/测试前期咨询

- **现象与需求：**鸿蒙设备覆盖讨论提升，部分小团队可能想知道现有应用是否值得适配；用户是小型软件商、门店系统开发者。
- **供给/渠道与流量：**以公开能力清单、测试报告样例获客，闲鱼作为咨询线索入口，私下按平台规则沟通与成交。
- **利润假设/收费：**按一次评估或小范围真机测试收费，收入取决于实际测试工时；不虚构“官方认证”。
- **低成本验证：**发布明确范围的适配检查服务，先问 10 个目标商家其现有设备分布和当前兼容问题，拿到 1 个付费试单再开发。
- **风险：**严禁误导官方背书；明确设备、系统版本、测试范围；客户代码与数据需保密，平台账号与售后争议也需管理。

### 小红书/抖音：品牌店铺运营问题拆解内容

- **现象与需求：**宝尊财报显示品牌经营涉及电商、线下门店、供应链和营销多个环节；中小商家往往缺少可对照的成本结构。
- **供给/渠道与流量：**发布匿名化案例方法论、库存/客服/投放核算表，通过垂直内容吸引店主，再转为诊断咨询。
- **利润假设/收费：**先做低价单次诊断，随后按月提供运营复盘；AI 可辅助归纳，不替代真实账目与平台数据。
- **低成本验证：**连续发布 3 个可复算的案例模型，观察有效私信与付费诊断转化，不买量、不刷互动。
- **风险：**不得泄露客户数据、盗用品牌素材或保证销量；广告、平台规则与售后退款需提前界定。

### 自建站/私域：政府项目资料模板与履约清单

- **现象与需求：**政策重申项目储备和支付使用，可能产生资料整理、进度记录和验收归档需求，但订单还要逐项核验。
- **供给/渠道与流量：**做可下载样例清单与公开招标文件解读页，以搜索流量、工程商转介和邮件订阅获客。
- **利润假设/收费：**模板一次性售卖或按项目提供整理服务；高客单服务须核验资质边界和交付责任。
- **低成本验证：**先做一个地区、一个工程门类的免费样表，访谈 5 家供应商，只有出现重复付费需求再做 SaaS。
- **风险：**不承诺项目中标、补贴或回款；避免处理涉密信息，遵守招投标、档案与个人信息要求。

## 创业/产品机会
