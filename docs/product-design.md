# 一手笔记整体设计

> 当前实现基线：2026-08-11
>
> Slogan：记录值得长期保存的知识

## 1. 产品定位

一手笔记是一个以 Markdown 为长期数据源的个人知识站。它不追求收集尽可能多的信息，而是把经过研究、完整阅读和持续筛选的内容整理成可以长期回看的知识。

当前包含四个主要内容模块：

| 模块 | 用途 | 内容入口 |
| --- | --- | --- |
| 技术 | 学习文档、内容拆解、人物与行业事件等长期文章 | `/blog/` |
| 面试 | 面向高级前端 / 前端负责人的 28 天 Session 学习站 | `/interviews/` |
| 书籍 | 基于用户提供原书的逐章精读笔记 | `/books/` |
| 晨读 | 技术、商业、创业、营销、金融、股市和基金信息 | `/briefings/` |

名词手册是文章阅读中的辅助能力，暂不作为独立的一级产品。

## 2. 已确定的体验

### 2.1 首页

首页是模块化内容看板，依次提供品牌与搜索入口、继续面试学习、今日晨读、正在精读、最新技术文章和长期专题。首页负责呈现当前最值得进入的内容，不作为全站内容的纯时间流。

### 2.2 书籍

书籍是独立模块：

- 书籍首页展示最近更新的章节，而不是最近更新的书。
- 全部书籍按分类平铺展示，分类默认展开。
- 分类筛选使用符合站点风格的自定义弹层，不使用浏览器原生下拉框。
- 点击书籍先进入书籍详情页，查看书籍信息和完整章节列表。
- 阅读页左侧固定为该书章节目录，中间为正文，右侧保留文章页目录。
- 当前章节必须高亮，并支持快速切换其他章节。

### 2.3 每日简报

每日简报是独立模块：

- `/briefings/` 展示最新一期、主题入口和历史简报。
- 简报阅读页左侧为日期归档，中间为正文，右侧保留文章页目录。
- 简报不进入首页文章流和普通文章分类统计。
- 内容覆盖 AI、开发、创业、营销、商业、金融、股市、基金，并可根据当天重要性动态调整。

### 2.4 前端面试

前端面试是独立的 28 天静态学习应用：

- 目标岗位是高级前端 / 前端负责人，全栈与 AI 工程能力作为加分项。
- 所有课程、知识卡、面试题、代码题和项目输出题都提前随站点构建，不在学习当天生成。
- 当前题库包含 96 个知识点、28 道实践题和 28 道输出题，共 152 项；Day 1 已扩充为 15 个知识点，并在首页直接预览真实题目；今日指标按当前实际可用题量封顶，避免出现无法完成的假进度。
- 每项参考答案采用“结论、展开、例子、面试表达”四段结构；评分点、继续追问、常见误区和官方参考保持独立，兼顾快速复习与口述训练。
- 浏览器以本地时间 04:00 作为学习日切换点；午夜后的连续学习不会被打断。
- 用户选择当前可用的 10、20、30、60 分钟或不限时，系统按到期复习、S 级薄弱点、今日专题、扫描、代码、项目与加练顺序组合 10～30 分钟 Session。
- 掌握度、复习日期、当前 Session、今日进度与记录保存在 `localStorage`，支持导出和导入。
- 未完成 S 级内容顺延，A 级在未来 2～3 天重新进入，B 级回到扫描池；只允许预扫描明后天的 B 级内容，首页可见的学习债务最多 45 分钟。
- 今日核心完成后仍提供加练，但不会大量提前解锁未来 S/A 级核心专题。
- 模块没有后端、AI 运行时或定时任务，完全兼容 GitHub Pages。

## 3. 当前技术架构

技术基座为 Astro 5 + Fuwari + Markdown，输出纯静态页面并由 GitHub Pages 托管。无需数据库、CMS、后端服务或常驻运行时。

### 3.1 内容源

```text
src/content/posts/       普通文章与名词手册
src/content/books/       一书一份元数据
src/content/book-notes/  逐章精读笔记
src/content/briefings/   每日简报
src/data/interview-plan.ts       28 天课程路径
src/data/interview-task-pool.ts  预置静态任务池
```

四个 Markdown 目录分别对应四个 Astro Content Collection：

```text
posts       普通文章和名词解释
books       书籍元数据
bookNotes   章节笔记
briefings   每日简报
```

`bookNotes.book` 使用 Astro `reference("books")` 引用真实书籍条目。引用不存在、字段类型错误或必填字段缺失时，构建直接失败。页面所需的书籍目录、分类统计和简报归档均在构建时从 Collection 查询，不保留 `.generated/` 内容投影层。面试模块使用经过 TypeScript 校验的静态数据，不属于 Markdown Collection。

### 3.2 顶部导航

桌面端与移动端使用同一套信息层级：

```text
首页 / 技术 / 面试 / 阅读 / 晨读 / 归档 / 关于 / 搜索
```

移动端仅折叠进菜单，不维护另一套分类。

### 3.3 稳定路由

```text
/                         模块化首页
/blog/                    技术文章列表
/blog/[slug]/             技术文章与名词解释
/series/[slug]/           技术系列
/books/                   书籍首页
/books/[book]/            书籍详情
/books/[book]/notes/[note]/  章节笔记
/briefings/               最新晨读与历史晨读
/briefings/YYYY/MM/DD/    指定日期晨读
/briefings/topics/[topic]/  晨读主题
/interviews/              28 天 Session 学习站
/archive/                 全站归档
/search/                  全站搜索
/about/                   关于
/rss.xml                  RSS
```

发布日期不进入技术文章或书籍笔记的永久地址；每日晨读以日期作为唯一标识。三个正文路由共享 `ArticlePage.astro`，继续复用 Fuwari 的 Markdown、代码块、目录、搜索和 SEO 能力。面试学习站是独立的 Svelte 交互页。

### 3.4 构建与发布

```text
Markdown 源文件
  -> 四个 Collection 的 Schema 与引用校验
静态面试数据
  -> TypeScript 类型检查与客户端调度
  -> Astro 静态构建
  -> Pagefind 搜索索引
  -> dist/
  -> GitHub Actions
  -> GitHub Pages
```

本地命令：

```bash
npm run check
npm run build
npm run dev -- --port 4321
```

普通文章和书籍笔记先在本地构建、预览并由用户确认，再提交或推送。GitHub Pages 工作流只负责在 `main` 更新后重新构建和发布。

## 4. 写作与阅读 Agent

`.ai/` 是跨工具规则的唯一事实来源：

| 工作流 | 共享规则 | 用途 |
| --- | --- | --- |
| 研究型写作 | `.ai/writing-agent.md` | 技能文档、内容拆解、人物行业、大事件等 |
| 真读精读 | `.ai/read-book.md` | 基于用户提供 PDF/EPUB 的完整逐章精读 |
| 每日简报 | `.ai/daily-briefing.md` | 每日联网检索、筛选、去重、写作与发布 |

工具专属入口保持轻量，只负责指向共享规则：

- Codex：`AGENTS.md`
- Claude Code：`.claude/commands/write-article.md`、`.claude/commands/read-book.md`
- Cursor：`.cursor/rules/writing-agent.mdc`、`.cursor/rules/read-book.mdc`

书籍精读不能使用网络书评、摘要或模型记忆代替原书。普通文章可以联网研究，但必须区分事实、观点、传闻和推断，并在相关事实旁保留来源。

## 5. 每日简报自动化

每日简报由 ChatGPT 的定时任务在每天 10:00（Asia/Shanghai）触发，不使用 n8n。

```text
ChatGPT 定时任务
  -> 搜索过去 24 小时及持续发酵的重要信息
  -> 来源分级、交叉验证、与近期简报去重
  -> 生成 src/content/briefings/YYYY-MM-DD.md
  -> 内容检查与构建
  -> 提交并推送 GitHub
  -> GitHub Actions 发布
```

该自动化只获得“每日简报”范围内的定时发布授权。普通文章和书籍笔记仍执行本地预览后由用户明确批准发布的流程。检索规则、内容结构和失败处理见 `.ai/daily-briefing.md`。

## 6. 视觉基线

- Fuwari 是站点 UI 与阅读体验的基础，不再混入管理后台、Starlight 或其他主题体系。
- 品牌使用藏青、金色和暖白，Logo 由书本、笔尖和书签构成。
- Slogan 与导航栏 Logo 一起展示，不保留独立品牌介绍卡片。
- 各模块共享排版、卡片、明暗主题和响应式规则，仅通过图标和少量信息结构体现差异。
- 优先保证正文宽度、字体大小、章节切换和移动端阅读，不为装饰覆盖大量 Fuwari 变量。

## 7. 质量与权限

- 外部事实必须有可访问的来源链接。
- 争议内容必须区分已确认事实、单方说法、传闻和编辑推断。
- 精读笔记必须可追溯到原书阅读单元，原书和提取文本永不入库。
- 自动化校验失败时不得强行发布，应保留草稿并报告失败原因。
- 每次代码或规则改动都要提交独立 commit；除已授权的每日简报任务外，不自动推送。

## 8. 与旧方案的差异

已经从旧方案中修正：

- 不使用 n8n，定时工作由 ChatGPT 任务承担。
- 简报发布时间不是 11:00，而是每天 10:00。
- 已建立 `posts / books / bookNotes / briefings` 四个独立 Collection，并删除旧同步脚本和 `.generated/` 投影。
- 不将首页改造成包含所有模块的仪表盘。
- 不新增书籍详情中间页，书籍首页直接进入章节阅读。
- 普通文章、书籍章节和每日简报使用各自的语义化路由。
- 不引入 Ant Design、React SPA、数据库或传统 CMS。
- 不先建设 PRD、ADR、Task、Log 的完整文档体系；只在复杂决策确有维护价值时增加。

## 9. 后续更新优先级

1. 完善内容校验：重复简报日期、失效内部链接和缺失来源。
2. 为 Pagefind 搜索结果增加模块标识或过滤能力。
3. 按需增加分模块 RSS。
4. 为文章和简报补充更准确的结构化数据与分享图。
5. 按实际需要扩充书籍状态、封面、阅读进度和评分字段。
